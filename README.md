# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 导轴承判级（收拢后的唯一实现）

导轴承以前上导/下导温度散在**页面、动作、另存（导出）三处各写一遍**：上导按 65、下导按 60，
升级界值差 5 度，大负荷时同一台机会报出两种结论。现已收拢：

- `frontend/src/domain/bearing-policy.ts` —— **唯一判级实现**。上导温度、下导温度、油位高度、
  振动数值在同一个环节判级；正常 / 温度偏高 / 待检修三档界值与“连续两次偏高升级”的升级办法
  只写这一份。页面（`views/bearing`）、动作（提交检测/确认检修）、导出另存、检修待办入口
  全部通过 `frontend/src/api/bearing-service.ts` 调用，不再各自判。
- `frontend/src/views/repair-todos/index.vue` —— 检修班组的**另一个入口**。判成「待检修」的导轴承
  自动落待办清单；班组在这里或导轴承页确认检修，调的是同一个 `confirmRepair`，确认后轴承标记、
  待检修台数、看板汇总三处同步回落。
- 汇总数字只从 `bearing-service.ts` 的 `bearingSummary()` / `listRepairTodos()` 取，汇总条与台账同源。

**界值（v1-2026 版，上导/下导统一）**

| 监测量 | 正常 | 温度偏高（警戒） | 待检修 |
| --- | --- | --- | --- |
| 上导/下导温度 | <60℃ | ≥60℃ | ≥65℃ |
| 油位高度 | 200～400mm | 越出区间 | 越界超过 20mm |
| 振动数值 | <0.10mm | ≥0.10mm | ≥0.15mm |

依据：温度报警/事故取轴承瓦温通行的 60/65℃（上导下导统一，消掉旧版 5 度差）；油位按油标正常
区间 200～400mm 与 10% 越界裕度；振动取 GB/T 11348.5 的 0.10/0.15mm。调整界值只能在导轴承页面
**发布新版本**（只追加、不改旧版），系统按新版整链重算所有已处理轴承；每条记录的历史结论
（等级 + 当时版本号）原样保留，台账同时显示“历史结论@版本”和“当前结论”。

**几条已定的业务规则（需求里授权“由你决定”的部分）**

- *两边取值冲突以哪份为准*：以**先落到 service 层并持久化的第一笔**为准。页面不缓存自己算的
  结论，提交、并发、导出都重读同一份状态，从根上消掉两种结论。
- *同一班次重复 / 同一时刻并发*：同一轴承同一班次（检测日期+班次）只受理第一笔；后到者（含同一
  时刻并发、其它标签页写入）按重复退回，取值留在“退回记录”表里留痕。写入前强制重读磁盘 +
  `storage` 事件作废缓存。
- *早年只记了上导温度怎么补下导*：按下导温度缺失条目的**温差法**——优先取同一轴承自己成对实测的
  平均温差（下导≈上导−温差），没有则用全厂成对记录平均温差，再没有按通行 3℃ 兜底；油位/振动
  早年未测的按同轴承最近实测值就近借用、借不到取正常中值。所有补齐量标“推算”，且推算记录
  **不作为“连续两次偏高升级”的依据**。
- *老台账迁移*：保留原编号（#1/#2/#3 等）与既有结论，按检测日期（业务时间）排序回填，历史结论
  标注 `legacy-pre2026` 版本；迁移后状态存独立键 `hydropower-plant-om:bearings:v1`，不再混入通用
  `entries`。想回到迁移后初始状态：清掉这个 localStorage 键。
- 导轴承已从通用模块框架（`data/modules.ts`）摘除，其它模块不受影响。

验证：`cd frontend && npm run test:bearing`（24 条用例，覆盖判级、升级、回填、迁移、去重并发、
检修回落、发版重算、待办对账与导出同源）。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts`（通用模块）或 `bearing-service.ts`（导轴承专属判级）里改，
  页面组件不做业务判断。
- 想回到初始数据：通用模块清 `hydropower-plant-om:entries`，或调用 `resetModule(模块)`；
  导轴承清 `hydropower-plant-om:bearings:v1`，或调用 `resetBearingState()`。
